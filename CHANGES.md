# Changelog

## [Unreleased]

### Mosaic

#### Added

- **Driving a program by its steps** – `Mosaic.start app f` runs `app` with the waiting left to `f`: `Mosaic.step r ~now` has the program take and act on its run's next step (`` `Stepped ``, `` `Idle `` until one of `Mosaic.fds r` is readable or `Mosaic.deadline r` comes, `` `Stopped `` once it is over), so a program waits with its own event loop. `Mosaic.dispatch r msg` gives the program a message from any thread, domain or fiber. The run itself stays Mosaic's: the caller never holds its `Matrix.app`
- **Highlighted editing** – `textarea ~syntax` takes the syntax settings of a code view: a highlighter receives each accepted text with the edit from its latest result, and while a result is pending the text keeps the styling of the bytes it shares with the last one. `~annotations` stays for styles the application resolves itself, such as search matches, and goes over the syntax colors (`Text_buffer.Annotations.merge`)
- **Running a program in the terminal** – `Cmd.exec f` gives the terminal to `f` (an editor, a pager) and dispatches its result once the terminal is taken again; `Cmd.suspend` stops the job as Ctrl+Z does in a shell
- **Workers** – `Sub.worker ~id f` runs `f stop mailbox` off the loop while `id` is declared, and requests its stop (`Sub.Stop.requested`, `Sub.Stop.on_request`) in the update that drops it or when the run ends; its messages are dropped from then on. `mailbox.dispatch` never blocks; `mailbox.send` returns once `update` has applied the message, for work that must keep pace with the loop. `Cmd.perform` takes the same mailbox
- **One-shot timers** – `Sub.after ~id delay msg` dispatches `msg` once, `delay` seconds after `id` appears in the subscriptions; dropping `id` first cancels it, so a debounce is an `after` declared under a new id by each update that restarts the wait
- **Shortcut subscriptions** – `Mosaic.Shortcut` and `Sub.on_keys` bind keys to messages declaratively, with base-key and modifier matching
- **Runtime probe** – `Mosaic.run ~probe` hands test harnesses a quiescence probe (`Probe.is_settled`) for deterministic settling in headless tests
- **Idle-cheap timers** – a pending `Sub.every` arms a one-shot wakeup instead of holding the render cadence live; only `Sub.on_tick` keeps the cadence running
- **Syntax API** – `Code.syntax` replaces the widget's public `spans` argument; `Code.Highlighter` runs highlighting synchronously or asynchronously with cancellation, stale-result protection, and a plain-text fallback
- **A stalled paste can be ended** – `Sub.on_paste_stalled seconds msg` reports a paste in progress that has received nothing for `seconds`, and `Cmd.abort_paste` ends and drops it. A paste still ends only at its end marker: one whose marker never comes takes every later key as content, Ctrl+C included, and the application decides when to give up
- **Terminal commands** – `Cmd.set_clipboard`, `Cmd.copy_selection`, `Cmd.clear_selection`, `Cmd.bell`, `Cmd.notify`, and `Cmd.query_color_scheme` paired with `Sub.on_color_scheme`
- `scroll_bar` and `diff` widgets; `diff` renders unified and split patches with per-line signs, highlighted source lines, sub-line highlight spans, line click hits, and source-row reveal
- `Mosaic.viewport_switch` picks a subtree by terminal width before layout, keeping compatible keyed children across the switch
- `scroll_box` takes keyed one-shot `?reveal`, `?scroll_by`, and `?reset_sticky` requests with `?on_scroll_by_applied` / `?on_reset_sticky_applied` acknowledgements, plus `?show_scrollbars` for a bare scrolling surface
- `markdown` takes a `?highlighter` and a `?syntax_style` that highlight fenced code blocks, and `?on_selection` reporting the selected rendered text
- `table` gains passive selection, overflow indicators, hover and activation callbacks, and PageUp/PageDown paging over its measured visible rows
- A drag that reaches a scroll box edge auto-scrolls and keeps the selection in sync with the new viewport
- Viewport culling for scroll containers and a clean-frame layout skip: off-screen children are neither laid out nor rendered, and layout recomputes only when the tree is dirty
- Scroll containers emit hardware scroll hints: an alt-mode scroll-by-one now reaches the terminal as a DECSTBM row shift plus edge-row diffs
- Widgets follow the terminal-negotiated width method instead of hardcoding Unicode tables

#### Changed

- `Mosaic.run ?input ?output ?env` (and `Mosaic.start`) replace `?backend`, as `Matrix.run` takes them
- **Highlighting builds on the latest result** – a `Code.Highlighter` request carries `previous`: the content of the view's latest result, the state the highlighter returned with it, and the one edit from it in bytes, derived by the view. `sync`, `threaded` and `async` take a `'state request` and return the captures with the highlighter's state; a highlighter that keeps nothing returns `()`. Results stay whole: a tree-sitter highlighter parses again from its edited tree and queries the whole new one, so a keystroke in 1 MB of OCaml under tree-sitter-ocaml's highlights.scm costs the worker about 110 ms instead of 240. `doc/highlighting.md` shows the recipe
- **Concealment is a property of the view** – `Code.create`, `Code.Props.make` and the `code` element take `?conceal`; `Code.syntax` and `Code.with_highlighter` lose it. `Diff.syntax` keeps its `?conceal` and passes it to its panes
- **Widgets list the keys they act on** – `select`, `tab_select`, `table`, `tree`, `scroll_box`, `scroll_bar`, `textarea`, `text_input` and `button` document, in their interfaces, every key their behavior acts on when focused; those keys are consumed and reach no ancestor and no `Bubble` listener, and every other key passes on. A focused `button` now consumes the Enter or Space that activates it
- **Listeners have a phase** – `Sub.on_key`, `on_keys`, `on_mouse` and `on_paste` take `?phase`. A `Bubble` listener, the default, runs after the elements and sees every event no element stopped, prevented or not; a widget behavior that acts stops the key, and `on_keys` skips a prevented key, so `Sub.on_keys [ (Shortcut.char 'q', Quit) ]` no longer quits while `q` is typed into a focused input. `Sub.on_mouse` now also sees the mouse events an element prevented without stopping, and reads `Event.Mouse.default_prevented` to tell. A `Capture` listener runs before the elements and sees every event; stopping an event never hides it from another listener of the application. `on_key_all`, `on_mouse_all` and `on_paste_all` are gone (use `~phase:Capture`), and `Sub.On_key`, `On_mouse` and `On_paste` carry the phase
- **Events go along a path, as in the DOM** – a key or a paste, like a mouse event, goes along a path taken when it is dispatched: the target's handlers, then its behavior (the character a key types, the text a paste inserts), then each ancestor's handlers, where keys and pastes reached the focused node only. The behavior runs on the node focused when it runs. `stop_propagation` keeps an event from the nodes after the current one, never from the current node's other handlers, and cancels no behavior; `prevent_default` cancels the behavior and the renderer's defaults. A behavior that acts stops the event. A press reaches its handlers before its defaults (text selection, the caret, the click), which a handler can now prevent. `Renderer.dispatch_key`, `dispatch_paste` and `dispatch_mouse` lose `?capture` and take a path from `Renderer.focus_path` or `Renderer.mouse_path`; `Renderable.set_default_key_handler` and `set_paste_handler` are `set_key_behavior` and `set_paste_behavior`; `Renderable.Private.emit_mouse` runs one node's handlers
- Frame deltas are seconds everywhere, as `Sub.on_tick`'s `dt` (canvas `on_draw`, renderable frame hooks, `Renderer.render_frame`); `Spinner.frame_set`'s `interval` is in seconds
- Selection/value props are controlled when provided and uncontrolled otherwise, uniformly across `slider`, `select`, `tab_select`, `table`, and `tree`
- Editable widgets take key bindings and aliases, and user paste handlers run before widget default paste behavior, matching OpenTUI's default-prevention semantics
- **Shortcuts match exactly** – a shortcut matches the key and its modifiers, then the base-layout key; the lowercase fallback, keypad normalization and Alt-implies-Meta are gone, `char ~shift:true 'r'` is `'R'`, and `Line_feed` bindings are Ctrl+J. Editors insert the keystroke's text; key releases reach `Sub.on_key_release`, never widgets; a paste reaches widgets whole once it completes
- `Cmd.focus` expires after one deferred attempt instead of retrying forever; every-timers carry absolute deadlines and no longer phase-merge
- Incremental markdown reconciliation: streaming appends re-render only the tail; `table` caches auto column widths; `line_number` indexes its props
- **Undo works in steps** – an `Editor` keeps its whole undo history as inverse changes, each costing the size of its change, and groups typing with no clock: typing, `delete_backward` and `delete_forward` each join the step they continue at the caret, until the caret moves, the selection changes or the kind of edit changes. A space after other text, other text after two or more spaces, and a line break start a new step; a paste, a word or line deletion and `clear` are steps of their own
- **Text follows the screen's width method** – a text buffer holds no width method: `Text_buffer.create` loses `?width_method`, `width_method` and `set_width_method` go, and `line_width` and `max_line_width` take the method to count by. Text, Code, editors, spinners, canvases and static output measure and paint by the screen's method at the time, and the renderer measures every node again when it changes, so a terminal that reports its method after the first frame no longer leaves existing widgets laid out by the old one
- **Primary frames are laid out once** – `Renderer.render_frame` is `Renderer.layout_frame` followed by `Renderer.paint_frame`, and loses `?layout_height`. In primary mode the runtime lays the frame out when it reports the rows it requires and paints that layout into the live region, where it laid the tree out once to learn the rows and again to draw; input geometry is laid out against the terminal's height too, so the tree is no longer laid out at two heights in turn

#### Changed (runtime)

- **Work runs off the loop's domain** – by default `Cmd.perform` and `Sub.worker` run on threads of one helper domain, started with the first work and ended when it has none, where each perform had a thread on the loop's domain: computing work no longer holds up keys, and a program that ran a perform no longer wakes 20 times a second once it is idle. While the helper domain runs, `Unix.fork` raises
- **`Cmd.batch` order is promised** – a batch starts its commands in list order, depth first, so terminal commands take effect in that order; the messages of work done off the loop arrive as it finishes. `Cmd.quit` ends the run once its update's commands have started, and drops the events read after it
- **Each tick has its own `dt`** – `Sub.on_tick` ticks once per frame with the time since that subscription's previous tick, `0.` on its first; it was the time since the previous frame, so an animation started after ten idle seconds began with a ten-second step
- **A late timer fires once, with a count** – `Sub.every ~id period f` dispatches `f k`, `k` the periods that ended since its previous call: `1` on time, more after a stall, where it replayed every missed period one turn at a time. Timers that come due in the same turn fire in the order of their grid points
- **`Mosaic.run ?backend ?config`** replaces `?matrix`; `init` runs before the terminal is taken, its commands and the first subscriptions inside the run, so an exception in either gives the terminal back. Work done off the loop dispatches through `Matrix.post`; `every` deadlines are exact integer nanoseconds; `on_tick` runs only in frames

#### Fixed

- An exception raised in a `Cmd.perform` ended its thread and printed over the screen while the program went on; it now ends the run, which gives the terminal back and raises it with the worker's backtrace
- A message dispatched from another thread was applied only at the next event or frame, outside the turn's budget, so a flood of them held the screen; it is applied when the loop takes it
- `Cmd.perform` messages can no longer be lost to a cross-thread race
- `Sub.on_mouse` and `Sub.on_paste` now see event consumption (they behaved like the `_all` variants)
- A mouse event a widget stopped reached only the first `Sub.on_mouse_all` listener; every capture listener now sees it
- A focused `scroll_box` took arrows and h/j/k/l along an axis it does not scroll; those keys now pass on to shortcuts
- Left-click focuses selectable widgets even when it starts a selection; wheel over dead space reaches the focused scrollable
- Tree and `select` mouse handling uses widget-local coordinates; `scroll_bar` applies orientation and arrow-color prop updates
- Reconciler tracks id changes on reused fibers, keys duplicates first-occurrence-wins, and places children in linear time
- Reordering keyed elements no longer detaches and reattaches reused nodes, so focus survives the reorder
- Text measurement no longer feeds back on the previous frame's width: no-wrap text measures untruncated, and wrapped text measures at its natural width under max-content, so a node can grow back after a shrink
- Terminal extents derive from rounded absolute edges, so adjacent flex children no longer paint over each other; clipping containers keep at least one cell
- Render work scheduled during a frame settles on the next frame instead of waiting for unrelated input, and superseded render passes no longer leak cells into adjacent widgets
- Sticky scroll boxes re-engage following when a reflow reaches the parked edge; `textarea` clamps scroll offsets on resize
- `table` and `tree` apply the `focused_selected_*` colors declared as props
- Word motions treat newlines as boundaries in the edit buffer
- Single-line editors reserve the caret cell, so an empty focused input shows its cursor
- Builds on OCaml 5.4 again (`Option.for_all` is 5.5-only)
- Typing inside a highlighted comment or string blanked all of it until the next highlight result; while a result is pending, a capture the change cuts through keeps its bytes on either side styled (`Syntax_highlight.conceals` names the captures that conceal, which show their bytes instead)

### Matrix

#### Added

- `Tty.readable fd` says whether a read would return without waiting (`poll(2)` with no timeout), allocating nothing and taking nothing from `fd`
- **Driving a run by steps** – `Matrix.step app ~now` is the next step at the time the caller gives, or `None` when the run has nothing to do until one of `Matrix.fds app` is readable or `Matrix.deadline app` comes; it never waits. `Matrix.next` is that loop waiting with `select(2)`, and allocates nothing while idle. A program with an event loop of its own waits with that loop instead, and a test or a replay gives the steps the times of its own clock: a step is a function of the run's state, its input and `now`, which must never decrease (`Invalid_argument` otherwise) and must be on the clock `deadline` answers in, `Matrix.clock` or a test's own
- **A run on any terminal, with its session's environment** – `Matrix.run ?input ?output ?env` takes the terminal on any pair of descriptors, and guesses its capabilities from the environment of the session it runs (`TERM`, `COLORTERM`, `NO_COLOR`…) rather than the process's: a served session runs with its client's. A served session runs on a pseudo-terminal pair the program pumps, and receives its size in band (`CSI 48 ; rows ; cols ; height ; width t`), before the run and on each change
- **Headless terminals (`matrix.test`)** – a pipe the test writes and a file it reads, under an ordinary `Matrix.run`: the test drives the run's steps with a clock it moves (`Matrix_test.now`, `advance`, `elapsed`), byte-level input goes through the real decoder, the size is reported in band, and frames are read as plain-text snapshots
- **Unicode text layer (`matrix.text`)** – grapheme iteration, width measurement, wrap-break and line-break discovery, and position helpers, independent of cell storage
- **Terminal charts (`matrix.charts`)** – declarative chart composition rendered into grids
- **Timer wakeups and paced one-shot redraws** – `Matrix.schedule_wakeup`, and `request_redraw` bursts coalesce to `target_fps`; `Matrix.request_immediate_redraw` renders one frame off-cadence
- **Primary-mode static output** – `Matrix.static_write ?preserve_live_region` keeps the live region across writes, `Matrix.static_replace` swaps all static content in one frame transaction, and `Matrix.static_clear` resets it
- Clipboard (OSC 52), desktop notifications, bell, and colour-scheme queries on `Terminal`, with tmux passthrough
- Scroll hints: `Matrix.set_scroll_hint` turns scrolling into a DECSTBM hardware scroll plus edge-row diffs
- **`Ansi.sanitize` for untrusted text** – keeps what shows, in order: every control function goes but HT and the line ends (CR, VT, FF and NEL end lines as LF does), and so do the characters a terminal shows as nothing (Default_Ignorable_Code_Point, all bidirectional controls among them), but for the variation selectors, joiners and flag tags that change how the character before them shows. `Ansi.strip` keeps CR, BS and BEL, and is not for untrusted text
- **Line feed/new line mode in the VTE** – `CSI 20 h` (LNM) makes LF, VT and FF also return to the first column, reported as `Vte.modes`'s `new_line`; feeding it first reads a program's output as a tty with output processing (ONLCR) shows it, with no option on `Vte.create`
- **A palette in the VTE** – `Vte.create ?palette` gives the terminal the colours its user configured, the 256 indexed colours, the default foreground and background and the cursor's colour, read back with `Vte.palette`. Programs set them with OSC 4, 10, 11 and 12, ask for them with a `?` spec, and reset them to the given palette with OSC 104 and 110 to 112, OSC 4 and 104 stopping at their first entry in error as xterm does; RIS restores the given palette and DECSTR keeps it. A change marks every row dirty, for a renderer that resolves the default and indexed colors through the palette. Without `?palette`, the colors are `Ansi.Color.indexed`'s, white (7) on black (0). The palette is the one owner of the default colors: `Vte.create` loses `?default_fg` and `?default_bg`, cells keep the default intent (`Ansi.Color.default_fg`, `default_bg`), and a renderer resolves default and indexed colors through `Vte.palette`
- **Application queries** – `Matrix.query app ~owed q` sends the application's queries as a batch closed by DA1, owed as the runtime's own are, and delivers their replies as `Matrix.Reply` events ending with the DA1 reply. Every DA1 reply is alike, so one batch that ends with DA1, the runtime's or the application's, is in flight at a time. A query sent with `Terminal.send` is not owed: its reply never reaches the application as a reply, and one that is a control string (DA3, XTVERSION, OSC 10/11, an OSC 52 read, XTGETTCAP) decodes as typing
- `Ansi.Parser.at_boundary` tells whether the bytes fed so far end inside a character, a sequence or a string, without ending the stream as `Parser.finish` does
- `Screen.Hit_grid.draw ~src ~dst ~x ~y` paints one hit grid's regions onto another at an offset, its empty cells leaving the destination unchanged, to embed a surface's hits in a larger one
- `Matrix_text.grapheme_cluster_break` is the Grapheme_Cluster_Break property of a character (UAX #29), as a variant with the short value aliases uucp uses
- `Grid.span g idx` is the start index and width of the grapheme that covers a cell, read from that cell alone, so a wide grapheme can be acted on whole from any of its cells
- `Ansi.Writer.of_bytes` writes into caller-owned bytes that it never replaces, raising `Ansi.Writer.Buffer_full` on a write that does not fit; `Screen.render_into` with such a writer renders a frame in memory the caller bounds, and a frame that does not fit commits nothing
- **Terminal descriptions (`matrix.terminfo`)** – `Matrix_terminfo.of_string` reads a compiled entry of the terminfo database in both of term(5)'s formats, the legacy one (0432) and ncurses' 32-bit one (01036), with the extended section of user-defined capabilities (`RGB`, `BE`, `Smulx`…) and their names; `flag`, `number` and `string` read any capability by its name, and `flags`, `numbers` and `strings` list them. `expand` evaluates parameterized strings as ncurses' tparm does, static variables (`vars`) included, and `pieces` cuts a string at its `$<…>` delays. On this machine it reads all 1,845 compiled entries as ncurses' own reader does (154,443 values) and expands 90,346 parameterized strings as tparm does. The 0.1.0 library, removed as unused, rejected every 01036 entry (`xterm-256color`), lost every string after the first absent one, ignored `%i` and read no extended capability. It links no unix
- `Ansi.Color.to_depth` reduces a color to what a terminal of a given depth shows (`Truecolor`, `Ansi256`, `Ansi16`, `Ansi8`, `Mono`), by the squared RGB distance xterm uses to show a direct color in its palette, reading no environment

#### Changed

- **The run is a scope, and the application pulls its steps** – `Matrix.run ?backend ?config (fun app -> ...)` takes the terminal for the scope and gives it back on every way out; inside, `Matrix.next app` returns the next `Event`, `Timer`, `Posted` message, `Frame` or `Stopped`, in an order matrix keeps: one step of each kind that has some, then events, timers and posts until done or one frame interval has passed, then the frame. A frame is drawn with `Matrix.draw app ?primary_required_rows (fun grid -> ...)`. `create`, `attach`, `close`, `stop`, `start`, `pause`, `running`, `suspend`, `resume`, `request_live`, `drop_live`, `schedule_wakeup`, `redraw_requested`, `request_immediate_redraw`, `prepare`, `submit` and `grid` go, as do the `create` knobs `target_fps` (now `config ~fps`, default 60), `pace_redraws`, `start_idle`, `resize_debounce`, `input_timeout`, `exit_on_ctrl_c`, `signal_handlers`, `mouse_enabled` and `output`
- **Frames on demand** – a frame comes only when asked for with `request_redraw`, at most `fps` a second; the first after a pause at once, and an animation asks again from each frame. An idle run waits with no deadline: it costs no wakeups (30 a second for `Matrix.create`'s continuous default before)
- **Time** – one monotonic clock, `CLOCK_MONOTONIC` from a C stub, in integer nanoseconds (`now : 'msg app -> int`, `Backend.now : unit -> int`); the `mtime` dependency goes. Deadlines are `Matrix.at` timers in one heap, cancelled with `Matrix.cancel`
- **Threads** – `Matrix.post app msg` is the one call another thread, domain or fiber makes; the app is typed by the message (`'msg app`), and every other call raises off the loop's thread
- **Resize** – the terminal's size is applied when the next frame is drawn, a storm of reports being one `Resize` with the usable size, returned just before that frame; the debounce goes. After a resize in primary mode, frames wait for the cursor report that places the live region; input does not
- **Signals** – C handlers write the wake pipe. SIGINT, SIGTERM, SIGHUP, SIGQUIT, SIGTSTP and SIGABRT are taken only at their default action; a termination signal gives the terminal back and is raised again, so the process ends with its status (143 for SIGTERM, 117 before); SIGTSTP gives the terminal back and stops the process; a SIGCONT it did not cause sets the terminal again; SIGABRT restores the terminal from its handler. Ctrl+C has no meaning in matrix: `Input.Keystroke.is_interrupt` tells it, and the application decides
- **Giving the terminal away** – `Matrix.release app f` replaces `suspend`/`resume`: it waits for owed replies, resets the modes, leaves the alternate screen (`leave_alt` goes), cooks the terminal keeping typeahead for `f`, gives `f` the default SIGTSTP/SIGTERM/SIGHUP and discards SIGINT/SIGQUIT received meanwhile, drops events typed after the step that released, and takes the terminal back with input left unread discarded. `Matrix.stop_job` stops the job as the suspend character would
- **Test harness** – `Matrix_test.backend` and `Matrix_test.config` for `Matrix.run`; time moves only when the test moves it (`advance`, `settle`); `stop` ends the input
- **Prefixed module names** – the sublibraries install `Matrix_grid`, `Matrix_screen`, `Matrix_input`, `Matrix_text`, `Matrix_terminal`, `Matrix_terminfo` and `Matrix_image` (Toffee likewise `Toffee_style`, `Toffee_tree`, `Toffee_geometry`, `Toffee_compute`) so they cannot collide with other packages' top-level modules; `Ansi`, `Vte`, `Pty` and `Tty` keep their bare names, terminal terms an application would not take for a module of its own (`Matrix_tty` is `Tty`); `Matrix_terminfo` keeps its prefix because compiler-libs has a `Terminfo`, and a program linking both fails to link. `Matrix` re-exports each sublibrary the runtime links under its short name: `Ansi`, `Grid`, `Input`, `Screen`, `Terminal`, `Terminfo`, `Text` and `Tty`
- **Input is decoded with no clock** – `Input.Decoder` replaces `Input.Parser` and `Input.Event`: one ordered stream of keystrokes (`Input.Keystroke`), mouse reports (`Input.Mouse_report`), paste, focus and replies (`Input.Reply`), the runtime saying when the terminal was silent. A keystroke has one value in every encoding: `Char` is the character typed with Shift consumed (Shift+a is `'A'`, and Caps Lock with a is `'A'` under the kitty protocol's associated text too), Ctrl+j is the old `Line_feed`, keypad keys are main keys with `keypad`, releases are `Key_release`, Alt no longer sets Meta, and bytes that are not UTF-8 are `Invalid`. A reply is never typed while its batch of queries is owed, and a control string begins only while a string reply is owed
- **The application's events are `Matrix.event`** – paste streams as `Paste_start`, `Paste_data` and `Paste_end` with no limit, and `Matrix.abort_paste` ends one; focus is `Focus_in`/`Focus_out`; `Text` carries text a terminal reports without a key. `create` lost `focus_reporting` and `` `Enabled flags ``, takes `?key_releases` and `?caps` (in place of `initial_caps`), and `Backend.t` carries the session's environment
- **Capabilities are derived, not accumulated** – `Terminal.Caps.derive` is a pure function of the environment, read once, and the answers so far, by one precedence: user policy, cited corrections, the answer of the terminal doing the work, identity, guesses. A late answer can take back a guess, and the runtime then changes the modes by their difference. Identity comes from the environment only when the terminal is directly attached; inside tmux, questions go to tmux itself, its facts come from its version when it is silent, and only questions about the outer terminal are wrapped, once passthrough has answered. The VS Code rule (no recorded reason) and `KITTY_WINDOW_ID` implying SIXEL are gone, and a color scheme report no longer implies mode 2031. On Windows, SIXEL and the kitty protocols are no longer turned off by a guess: they follow the terminal's answers, as everywhere else. The probe no longer sends iTerm2's `OSC 1337;ReportCellSize`, whose reply nothing used, and `identity` no longer records whether it came from XTVERSION or `TERM_PROGRAM`
- **The description of `TERM` is a guess** – `Caps.env ?terminfo` takes the description the terminfo database has for `TERM`, and `Backend.unix` gives it (`Tty.terminfo`). It only ever adds a fact, below every answer and identity: direct colour from `RGB`, `Tc` or `setrgbf` with `setrgbb`; bracketed paste from `BE`; focus reports from `fe`; synchronized output from a `Sync` that is mode 2026. Descriptions leave out direct colour and synchronized output for most terminals that have them (none of seven measured terminals' descriptions has either), so a description's silence takes nothing away
- **Input modes** – the startup probe sends S7C1T first, so no reply comes with 8-bit controls; focus (1004), color scheme (2031) and resize (2048) reports are set without asking, since xterm, kitty, foot and tmux ignore a private mode they do not know (their source); an XTWINOPS text-area report, `CSI 8 ; rows ; cols t`, no longer resizes: it is the reply to `CSI 18 t`, which the runtime never sends, and the in-band resize report is mode 2048's, so an application that asks with `Matrix.query` receives it as a `Reply`; metaSendsEscape (1036) is set where the terminal has it reset, and reset on exit; the kitty flags are pushed once the terminal answers, then asked for again; a batch of queries stays owed until its DA1, however late, or for max(5 s, 4 RTT) if the terminal never answers, while the runtime waits for an answer at most max(500 ms, 4 RTT); a late DA1 still measures the round trip, and the ESC and sequence waits scale with it; the probe's width tests are written on the second row, so their cursor reports are never a modified F3
- Colors are emitted at the terminal's negotiated depth: RGB downgrades to ANSI256 or ANSI16 when truecolor is unavailable, and indexed colors are preserved verbatim
- The Image DSL is its own `matrix.image` sublibrary; its aliases collapsed into one `text` constructor and one grid-order `draw`
- All screen buffers share one grapheme and hyperlink store, making the diff sound for complex cells and hyperlinks across frames
- `matrix.screen` drops legacy chaining and runtime-owned metrics; cursor state is a single zero-based value
- The render and submit paths are allocation-free at steady state (retained buffers and writers, unboxed bookkeeping, no per-frame string copies), and each frame leaves the terminal in a single write
- Strict VT100 semantics in the VTE: LF moves down only, BS is pure movement
- Raw mode no longer changes `O_NONBLOCK`; readiness is the backend's concern
- **The device is `matrix.tty`** – `Tty` has what the operating system knows of a terminal and does to it: `is_tty`, `is_controlling`, `window`, the monotonic clock `now`, and the line settings `raw`, `restore` and `flush_input`, with `enable_vt` for a Windows console, `terminfo`, which finds a terminal type's description as ncurses does (`TERMINFO`, a database or the description itself as `hex:` or `b64:`; `~/.terminfo`; `TERMINFO_DIRS`; the system's databases; first-character and hexadecimal directories; none of the variables in a setuid process), and `Signal`, the process's signals shared by every holder of a terminal in it, the runtime's runs among them, by one policy per signal that `Tty.Signal` states: the C handlers and the table of holders moved there from the runtime, which takes the signals through it. `Matrix_terminal` loses `raw_saved`, `set_raw`, `restore`, `size`, `is_tty`, `flush_input` and `enable_vt`, and links no unix and no C, so `matrix.terminal`, `Caps` with it, joins the libraries a unikernel can use. `Tty.window` is `None` where the system reports no size, where `Terminal.size` guessed 80×24; `settings` is abstract
- **The terminal core links no unix** – `matrix.screen` reads no clock: `Screen.create` and `Mosaic_ui.Renderer.create` lose `?clock`, and `Screen.frame_metrics` loses `frame_time_ms`, `interval_ms`, `reset_ms` and `timestamp_s`; the runtime times its renders on its own clock for the debug overlay. `matrix.ansi`, `text`, `grid`, `input`, `screen`, `image`, `charts` and `vte` link no unix, which a test checks, so a unikernel can use them; `matrix.image` reached unix through the screen's default clock
- **Replies are encoded where they are decoded** – `Input.Reply.encode` writes replies as a terminal sends them, and the decoder reads them back to the same values. An OSC reply (`Color`, `Clipboard`, `Osc`) keeps its `terminator`, BEL or ST, since xterm answers with the query's; `Cursor` carries DECXCPR's `page` (`None` for a CPR); DSR 5's answer decodes as `Operating_status`; `Reply.of_osc` takes the terminator; `Reply.rgb_of_spec` reads X11 color strings as XParseColor does, the `rgb:` and `#` forms and the color names of X.Org's rgb.txt (rgb 1.1.0, case-insensitive, spaces not counted), so a `#rrggbb` or named color reply decodes as `Color` and the VTE's OSC 4/10–12 take names. `Cut` and `Too_long` move from `Input.Reply.t` to `Input.Decoder.event`, so `Reply.t` is what a terminal sends and `encode` is total; the runtime drops them, where an application batch received them as replies
- **The VTE's replies are values** – `Vte.feed` and `Vte.feed_string` return the replies as `Input.Reply.t list`, `[]` with no allocation when there are none; a relaying caller writes `Input.Reply.encode replies`. The identity stays a VT100 with Advanced Video for every terminal: a caller that must pass for another rewrites the reply it relays, such as DA2 to `Secondary_attributes [0; 276; 0]` for xterm.js 5, where the promise is visibly its own. `Vte.create`'s `?da1`/`?da2` stay removed
- **The VTE reads by row** – rows run from the screen, `0` to `rows - 1`, up into the scrollback, `-1` the newest line; `Vte.text t y` is a row's text and `Vte.blit_row t y dst ~y'` its cells, with rendition, hyperlinks and widths, into a grid, for scrollback lines as for the screen, beside `Vte.wrapped`. `Vte.scrollback_lines` and `Vte.render_with_scrollback` go: `List.init n (fun i -> Vte.text t (i - n))` and a loop of `blit_row` replace them
- Backtrace recording policy is left to the application; the runtime prints a backtrace on an uncaught exception rather than enabling recording itself
- `Screen.render_to_bytes` removed (no consumers); `render_to_buffer` is the per-frame eliminator
- Vendored uuseg stripped to its boundary core; one shared grapheme-width state machine
- **Primary layout by scrolling** – the live region claims rows only by scrolling the rows above it into the terminal's scrollback, and static rows go at its top, so a transcript row is never overwritten. No scrolling margins (DECSTBM) are set, no blank row separates static output from the live region, and `static_write ~preserve_live_region` keeps the live height whatever is above it
- **Unicode 18.0** – `matrix.text`'s tables and its grapheme segmenter follow Unicode 18.0.0: 990 new wide characters take two cells and 31 new nonspacing marks none, and GB9c binds a consonant to the linker before it with no consonant before the linker (UAX #29 rev. 49), so `a्ष` is one grapheme
- **Conjuncts take one cell under `Unicode`** – a conjunct takes its first consonant's cell, in every script, as the grapheme cluster mode (2027) and kitty's text-sizing protocol place a cluster; Devanagari conjuncts took a cell per consonant (क्ष two cells), a rule from OpenTUI that no terminal measured follows and that left Malayalam's ക്ക at one
- **Emoji modifier sequences on a text-default base take two cells under `Unicode`** – ☝🏽 (U+261D U+1F3FD), ✍🏻 and the other sequences whose base has no emoji presentation of its own measure 2, where the modifier was ignored and they measured 1
- **A terminal without mode 2027 is measured by character** – `Terminal.Caps` gives `Wcwidth` when the terminal answers DECRQM 2027 with 0 (not recognized) or not at all, unless its identity says it places grapheme clusters (kitty, or `TERM` naming kitty), and the default width method is `Wcwidth`. An answer of reset (2) says the terminal can cluster with the mode off: `Unicode`, which the runtime sets the mode for and resets on exit; permanently reset (4) is `Wcwidth`. The runtime sets mode 2027 only where the terminal answered it reset (`Caps.t.grapheme_mode`), so a terminal that had it set, such as foot, keeps it after exit; `Terminal.set_unicode_width` is `Terminal.enable_grapheme_mode`. xterm, VTE and st, which matrix measured as `Unicode`, now get the method they draw by
- **A spacing mark has no width of its own under `Unicode`** – one that starts a cluster (U+093F alone, or after a lone combining mark) leaves it no cells, as kitty, WezTerm and foot draw it, where it took one; a wide one (U+302E) keeps two
- `Grid.active_height` counts every row that shows something a terminal's erase does not: a space with a background, an attribute or a hyperlink counts, not only a character. A primary-mode full redraw no longer erases a trailing row of background, and a static commit keeps it
- **Primary frames have their rows before they are drawn** – `Matrix.prepare ?primary_required_rows` grows the live region and sizes the frame to it, and `run` asks `primary_required_rows` before `on_render`, so a frame that needs more rows shows them, where the first grown frame showed only the old height. `Matrix.submit` no longer takes the rows; static writes go to the transcript in `prepare`, after which the live region still has the rows the frame requires. Mosaic lays its tree out before the frame to know them
- `Grid` reads and writes its cell planes with direct loads and stores, where every access called into the runtime: a full repaint takes a third of the time it took, and drawing a screen of text less than half
- `Screen.Hit_grid` fills its cells with direct stores, where every cell called into the runtime: a wheel event in a 250x70 Mosaic application costs a fifth of what it did, and a frame a quarter less
- **Colors at 256 colors are xterm's** – an RGB color reduced to 256 colors becomes the nearest of entries 16 to 255, whose colors every such terminal shares, never one of the 16 the user's theme sets, and a tie goes to the higher entry, as in xterm: `rgb(255,0,0)` is `38;5;196`, not `38;5;9`. `Sgr_state.color_depth` is `Color.depth`, which adds `Ansi8` and `Mono`, and the screen emits colors as `Color.to_depth` reduces them

## [0.1.0] - 2026-02-26

### Mosaic

Terminal UI framework for OCaml built on Matrix and Toffee. Implements The Elm Architecture (TEA) for declarative, composable terminal applications.

- **The Elm Architecture** – Pure functional Model-View-Update pattern with `init`, `update`, `view`, and `subscriptions`. Commands (`Cmd`) handle side effects; subscriptions (`Sub`) handle external events
- **Flexbox and Grid layout** – Powered by Toffee, define complex layouts with familiar CSS properties like `flex_direction`, `align_items`, `justify_content`, and CSS Grid support
- **Rich widget library** – `box`, `text`, `input`, `textarea`, `select`, `tab_select`, `slider`, `table`, `spinner`, `scroll_box`, `canvas`, `code`, `markdown`, `tree`, `progress_bar`, and `line_number`
- **Rich text** – Styled fragments, word/character wrapping, text selection, and full Unicode support
- **Syntax highlighting** – Tree-sitter-based code highlighting with the `code` widget
- **Event system** – Mouse, keyboard, paste, focus, and resize events with `Sub.on_key`, `Sub.on_mouse`, `Sub.on_paste`, `Sub.on_resize`, `Sub.on_focus`, and `Sub.on_blur`
- **Canvas drawing** – Procedural drawing API with shapes, lines, and braille patterns for charts and visualizations
- **Markdown rendering** – CommonMark rendering with the `markdown` widget
- **Dirty tracking and viewport culling** – Only re-layouts dirty subtrees; scroll containers cull off-screen children

### Matrix

Terminal toolkit for OCaml providing rendering, input, and terminal management.

- **Immediate-mode runtime** – `Matrix.run` with `on_frame`, `on_render`, `on_input`, `on_resize` callbacks, configurable FPS capping, and safe teardown that restores terminal state even on exceptions
- **Two display modes** – Full-screen alternate buffer (`Alt`) or inline on primary screen (`Primary`) with dynamic height and full scrollback
- **Declarative Image API** – Notty-inspired compositional DSL with `hcat`, `vcat`, `overlay`, padding, cropping, and hit regions for mouse interaction
- **Full Unicode support** – Grapheme cluster handling, emoji, wide characters, and configurable width calculation (wcwidth, Unicode tables)
- **Modern terminal protocols** – Kitty keyboard (with auto-detection), SGR/X10/URXVT mouse tracking, bracketed paste, focus reporting—all negotiated automatically
- **Native alpha blending** – RGBA colors with proper alpha compositing for translucent overlays
- **Double-buffered diffing** – Screen module diffs cell changes between frames to emit minimal ANSI output
- **PTY & VTE** – Spawn processes in pseudo-terminals and embed terminal output in your UI; cross-platform with Windows ConPTY support
- **Automatic capability detection** – Two-stage probing (environment heuristics + active queries) detects RGB, Kitty keyboard, sixel, hyperlinks, and Unicode width support without manual configuration
- **Hit testing** – O(1) spatial indexing maps mouse coordinates to UI element IDs for clickable widgets
- **Built-in devtools** – Debug overlay for frame timing/FPS, frame dumps to disk for diagnostics

### Toffee

CSS layout engine for OCaml, ported from [Taffy](https://github.com/DioxusLabs/taffy) (Rust).

- **CSS Grid Level 1** – Full implementation including `grid-template-columns/rows`, `grid-auto-flow`, named lines/areas, `repeat()`, `minmax()`, `fr` units, and auto-placement
- **Flexbox** – Complete algorithm with `flex-direction`, `flex-wrap`, `flex-grow/shrink/basis`, `align-items/self/content`, `justify-content`, `gap`, and `order`
- **Block layout** – Traditional CSS block formatting context with proper margin collapsing
- **Pure OCaml, zero dependencies** – No C stubs, no runtime dependencies; works wherever OCaml 5 runs
- **Arena storage and layout caching** – Nodes stored in a flat arena; layout results cached and invalidated via `mark_dirty`
- **Composable architecture** – Use the high-level `Toffee` tree API or the lower-level `toffee.tree` and `toffee.compute` libraries to plug layout into your own node representation
- **Custom measure functions** – Integrate text shaping, images, or any content with intrinsic sizing via `compute_layout_with_measure`
